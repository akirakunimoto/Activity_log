# 要求事項・要件

## 1. 目的

日々の睡眠・活動・運動を記録し、期間別に振り返れる個人用ツールを提供する。操作はローカルWeb画面から行い、記録データはユーザーの端末内に保存する。

## 2. 利用者と利用環境

- 利用者: 自分の活動データを記録・確認する個人。
- 操作方法: PC上でStreamlitアプリを起動し、ローカルブラウザーで操作する。
- 実行環境: Python仮想環境とStreamlit。保存先にはSQLiteを利用する。
- 外部サービス、アカウント、ネットワーク接続は記録や集計に必要としない。

## 3. 用語

| 用語 | 意味 |
| --- | --- |
| 日次データ | 1日につき1件保存する睡眠・歩数・リング等の値 |
| ランニング記録 | 日付、走行距離、所要時間からなる1回分の記録 |
| 筋トレセット | 日付、種目、重量、回数からなる1セット分の記録 |
| リング | Apple Watchのムーブ、エクササイズ、スタンドの3項目 |
| ペース | ランニング時間を距離で割った時間/km。小さいほど速い |

## 4. 機能要件

### FR-01 日次データの記録

日付を指定し、次の項目を任意に記録できること。

- 睡眠スコア（0〜100）
- 歩数（0以上の整数）
- 登った階数（0以上の整数）
- Apple Watchのリング3項目それぞれの実績値と目標値
- 筋トレ時間（分）
- メモ

同じ日付を再度保存した場合は、その日の日次データを更新する。リングの実績値と目標値は対で入力する。片方のみの入力はエラーとして案内する。
リング目標値の初期値は、ムーブ550 kcal、エクササイズ30分、スタンド12時間とする。初期値のみでは保存せず、実績と一緒に入力した場合に保存する。保存済みの目標値がある場合はその値を表示する。

### FR-02 ランニング記録

- 1日に複数回のランニングを登録できる。
- 1回ごとに距離（km）と所要時間（分）を記録する。
- 1回ごとのペースを `時間 ÷ 距離` で算出し、分/km形式で表示する。
- 日付を指定して既存記録を確認し、1件ずつ削除できる。
- 距離と時間はいずれも0より大きい値とする。

### FR-03 筋トレ記録

- 種目・重量（kg）・回数をセット単位で登録する。
- 種目は自由入力、または次の候補から選択できる。1セットにつきいずれか一方を指定する。
  - 01_ショルダープレス、02_チェストプレス、03_ラットプルダウン、04_バイセップスカール、05_ディップス、06_レッグプレス
  - 07_アダクション、08_アブダクション、09_アブドミナルトレーナー、10_アブベンチ、11_トレッドミル、12_バイク
- 同じ種目を複数セット記録でき、セットごとに重量や回数を変えられる。
- 日付を指定して既存セットを確認し、1件ずつ削除できる。
- 重量は0以上、回数は1以上の整数とする。
- 日次の筋トレ時間はセット内容とは別に入力する。時間が不明でもセットを登録できる。

### FR-04 リング達成率

| リング | 実績値・目標値の単位 |
| --- | --- |
| ムーブ | kcal |
| エクササイズ | 分 |
| スタンド | 時間 |

各リングの達成率を `実績値 ÷ 目標値 × 100%` で表示する。画面上の進捗バーは100%で上限とするが、表示文字列には100%を超えた実績率を表示する。Apple Watchとの自動連携は本版では行わず、値は手入力する。

### FR-05 振り返り・集計

- 日・週・月の集計単位を選べる。
- 対象期間を日付範囲で指定する。
- 選択期間の記録一覧を表示する。
- グラフにする項目を選択し、時系列で確認できる。
- ランニング時間、ランニング距離、ペース、筋トレ時間、筋トレ総負荷、睡眠スコア、歩数、階数、リング達成率を確認できる。
- 期間全体のランニング時間・距離と筋トレ時間を表示する。ランニング時間と筋トレ時間は独立して集計し、相互に合算しない。
- 日次データが存在しない期間は、空状態を表示する。

## 5. 非機能要件

### NFR-01 ローカル保存とプライバシー

- 記録を外部サービスへ送信しない。
- OSによらず、ワークスペース直下の `activity.sqlite3` に保存する。
- ワークスペースがOneDrive等の同期対象内にある場合、DBも同期される。DBファイルはGitの追跡対象から除外する。
- バックアップはアプリ終了後にSQLiteファイルをコピーして行える。

### NFR-02 データ整合性

- DBのトランザクションで各保存処理を確定する。
- SQLはパラメーター化し、値をSQL文へ直接埋め込まない。
- 日次の値にはPython側の検証とSQLiteの制約を適用する。
- 削除操作は対象の記録1件に限定する。

### NFR-03 保守性・実行性

- 保存層、集計ロジック、画面を分離する。
- 型チェックと自動テストをローカルで再現できる。
- Python仮想環境と依存関係定義を使う。

## 6. 対象外

- Apple Health / Apple Watchからの自動インポート、同期、認証。
- 複数ユーザー、ログイン、共有、クラウド同期。
- モバイルネイティブアプリ、通知、運動計画の提案。
- CSVインポート・エクスポート、バックアップの自動化。
- 睡眠時間や睡眠段階の記録（本版で指定された睡眠項目はスコアのみ）。

## 7. 受け入れ条件

1. 画面から日次データを保存し、同じ日付を再選択した際に保存値が再表示される。
2. リング実績と目標値の片方だけを入れた場合、保存を拒否して説明を表示する。
3. 同一日に複数のランニングを登録でき、それぞれのペースが距離と時間から計算される。
4. 複数の筋トレセットを追加・確認・個別削除できる。
5. 日・週・月の単位を選択し、指定項目のグラフと期間の記録一覧を表示できる。
6. ランニング時間と筋トレ時間が個別に表示され、合算されない。
7. 記録がない期間に例外が発生せず、空状態が表示される。
8. 記録DBがワークスペース直下に作成され、Gitの追跡対象外である。
