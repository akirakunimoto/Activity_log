# 詳細設計

## 1. システム構成

```text
利用者
  └─ ローカルブラウザー
       └─ Streamlit UI (streamlit_app.py)
            ├─ 保存・取得 (activity_log/storage.py)
            │    └─ SQLite (ワークスペース直下/activity.sqlite3)
            └─ 計算・集計 (activity_log/analytics.py)
```

アプリの主な構成要素:

| ファイル | 責務 |
| --- | --- |
| `streamlit_app.py` | 記録画面、振り返り画面、入力・操作結果の表示 |
| `activity_log/storage.py` | DB初期化、入力検証、日次・ランニング・筋トレデータの読み書き |
| `activity_log/analytics.py` | ペース・時間表示、日週月の集計、リング達成率計算 |
| `tests/` | 保存処理と集計ロジックの自動テスト |

## 2. 画面設計

### 2.1 記録画面

画面上部の切替で「記録」「振り返り」を選ぶ。記録画面では記録日を選び、同日の日次値と個別運動記録を表示する。

1. **日次データ**: 睡眠スコア、歩数、階数、3リングの実績・目標、筋トレ時間、メモをフォームから保存する。
2. **ランニング**: 距離・時間を入力して1回分を追加する。登録済み記録は距離、時間、ペースを一覧表示し、個別に削除できる。
3. **筋トレ**: 編集可能な複数行テーブルで、種目を自由入力または候補から選択して重量・回数とともに入力し、フォーム送信時にセットを追加する。登録済みセットは一覧表示し、個別に削除できる。
4. **リング達成率**: 保存済みの実績と目標の組について、達成率を進捗バーと文字で表示する。

日次データの保存はその日付の各フィールドを置き換える。未入力欄はNULLとして保存され、以前の値があった場合も空欄で保存すればクリアされる。ランニング・筋トレの個別行は日次データ更新では変更されない。
リング目標値が未保存の場合、ムーブ550 kcal、エクササイズ30分、スタンド12時間を初期表示する。初期値のみでは保存せず、実績と一緒に入力した場合に保存する。保存済みの目標値は初期値で上書きしない。

### 2.2 振り返り画面

- 集計単位: 日、週、月。
- 初期表示期間: 今日を含む直近90日。
- 記録が存在する期間について、ランニング時間・筋トレ時間・ランニング距離の期間合計カードを表示する。
- グラフ項目を選び、期間で集計した推移を棒グラフで表示する。
- 集計表には日付、睡眠、歩数、階数、ランニング、筋トレセット数、リング達成率等を表示する。

### 2.3 入力エラーと空状態

- アプリ層で理解可能な入力エラー（リングの片側入力、筋トレ未入力等）は利用者向けに表示する。
- 保存層の値域制約にも違反した値は保存しない。
- 履歴なし、選択期間なし、項目データなしは空状態として表示する。
- DB障害など想定外の例外を成功扱いにしたり、空データとして隠したりしない。

## 3. データモデル

SQLiteは起動時に `CREATE TABLE IF NOT EXISTS` で初期化する。日付はISO 8601形式の `YYYY-MM-DD` で格納する。

### 3.1 `daily_logs`

日付ごとの任意項目を保持する。主キーは `activity_date`。

| 列 | 型 | 制約・意味 |
| --- | --- | --- |
| `activity_date` | TEXT | 主キー、ISO形式の日付 |
| `sleep_score` | INTEGER nullable | 0〜100 |
| `steps` | INTEGER nullable | 0以上 |
| `floors_climbed` | INTEGER nullable | 0以上 |
| `move_kcal` / `move_goal_kcal` | REAL nullable | 実績0以上、目標0より大きい |
| `exercise_minutes` / `exercise_goal_minutes` | REAL nullable | 実績0以上、目標0より大きい |
| `stand_hours` / `stand_goal_hours` | REAL nullable | 実績0以上、目標0より大きい |
| `strength_minutes` | REAL nullable | 0以上 |
| `note` | TEXT | NOT NULL、既定値は空文字 |

リングの実績と目標は同時にNULLか、両方入力済みとする。このペア制約と有限数値チェックは保存層の入力検証で行う。

### 3.2 `running_sessions`

| 列 | 型 | 制約・意味 |
| --- | --- | --- |
| `id` | INTEGER | 主キー |
| `activity_date` | TEXT | `daily_logs.activity_date`への外部キー。日次行削除時に連動削除 |
| `distance_km` | REAL | 0より大きい |
| `duration_seconds` | INTEGER | 0より大きい。UI入力の分を秒に変換して保持 |

日付検索用インデックス `idx_runs_date` を持つ。1日の複数回のランニングを複数行で表す。表示ペースは `duration_seconds / 60 / distance_km` 分/km。

### 3.3 `strength_sets`

| 列 | 型 | 制約・意味 |
| --- | --- | --- |
| `id` | INTEGER | 主キー |
| `activity_date` | TEXT | `daily_logs.activity_date`への外部キー。日次行削除時に連動削除 |
| `exercise` | TEXT | 空白のみ不可 |
| `weight_kg` | REAL | 0以上 |
| `repetitions` | INTEGER | 1以上の整数 |

日付検索用インデックス `idx_strength_sets_date` を持つ。種目名が同一でも別セットの行として保持する。筋トレ総負荷の集計値は各セットの `weight_kg × repetitions` の合計。

### 3.4 集約用データ

履歴取得時に、ランニングは日付ごとの距離合計・秒数合計を分に変換し、筋トレセットは日付ごとのセット数・総負荷を集約する。これらを日次データにLEFT JOINし、日付範囲内で返す。

## 4. 集計ルール

| 項目 | 日 | 週・月 |
| --- | --- | --- |
| 睡眠スコア | 日の値 | 平均 |
| 歩数、階数 | 日の値 | 合計 |
| リング実績・目標 | 日の値 | 各々を合計してから達成率を算出 |
| ランニング距離・時間 | 日合計 | 合計 |
| ランニングペース | 日の時間合計÷距離合計 | 期間の時間合計÷距離合計 |
| 筋トレ時間 | 日の値 | 合計 |
| 筋トレセット数・総負荷 | 日の集計 | 合計 |

- 週は月曜開始・日曜終了（`W-SUN`）、月は暦月（`MS`）で集計する。
- ペースは距離が0の場合は未定義（NaN）とし、0除算を行わない。
- リング達成率は集計期間内の実績合計÷目標合計。目標値がない期間は未定義。
- 空欄の筋トレ時間は合計時に除外する。全日が空欄の場合は合計0分として表示する。
- 振り返りの日次データ行が存在する日のみが日付系列に含まれる。記録のない日付を0として補間しない。
- ランニングと筋トレの所要時間は意味が異なるため、合算しない。

## 5. データ保存とトランザクション

- OSや起動時の作業ディレクトリによらず、ワークスペース直下の `activity.sqlite3` に保存する。保存先は `storage.py` の配置を基準に解決する。
- DB接続はトランザクション管理コンテキストを使い、例外時はロールバックする。
- すべての利用者入力値はSQLプレースホルダー経由で渡す。
- バックアップの正式手順はアプリを終了後にDBファイルをコピーすること。ワークスペースがOneDrive等の同期対象内にある場合、DBも同期される。
- `activity.sqlite3` とSQLiteの一時ファイルは `.gitignore` でGitの追跡対象から除外する。

## 6. 技術・依存関係

- Python 3.14.2のワークスペース仮想環境で開発する。
- StreamlitがUI、SQLiteが永続化、pandasが集計結果の時系列処理を担当する。
- 本版ではユーザー管理、外部API、ネットワーク送信の仕組みを持たない。
- 依存関係の一覧はワークスペース直下の `requirements.txt` と `requirements-dev.txt` を参照する。

## 7. 既知の制約

- 日次データは日付単位で1件。時刻別の睡眠や歩数記録には対応しない。
- 実績値は手入力で、Apple Watchとの同期・データ検証は行わない。
- 筋トレ時間は日次の独立した値であり、セットから自動算出しない。
- 振り返りグラフの筋トレ総負荷は「重量×回数」の合計で、距離・時間等とは同一尺度で比較できない。
- CSV形式のデータ移行・エクスポート機能は未実装。
